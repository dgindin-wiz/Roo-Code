## Issue-First Codex Default

For non-trivial GitHub engineering work:

- start from a tracked work item before implementation
- prefer GitHub Issue + branch + Pull Request
- keep durable state in the work item, not only in chat
- record validation before saying work is ready for review
- use the `issue-first-workflow` skill for detailed behavior
- read repo-local `.codex/process.md` when present

Do not silently mix unrelated work into the same branch, Issue, or PR.
